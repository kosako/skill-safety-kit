# スキルの安全チェック ガイド — 考え方と使い方

エンジニアでない方向けに、「スキルをチェックする」とはどういうことか、なぜ必要か、
どう使えばいいかをまとめたガイドです。専門用語はできるだけ使いません。

## 1. スキルとは何か、なぜチェックが要るのか

スキルは「AI への作業手順書」です。Claude Code や Claude Cowork に読み込ませると、
AI がその手順に従って仕事をするようになります。便利な半面、**手順書に書いてあることを
AI は素直に実行してしまう**ので、次のような危険があります。

- 手順書の中に「秘密情報を外に送れ」のような**悪意ある指示**が紛れている
  (見えない文字で隠されていることもあります)。
- 悪意はなくても、**確認なしでメールを送る・予定を書き換える**ような危なっかしい
  作りになっている。
- 作った人のパソコンの情報 (個人のフォルダ名など) が**うっかり混入**している。

なお、スキルには手順書 (文章) だけでなく、**AI が実行できるプログラム (スクリプト) が
同梱されている**ことがあります。プログラムは文章より強いことができる分、点検も
慎重になります (後述の「プログラム入りのスキル」)。

これはブラウザの拡張機能や Excel のマクロを組織で使う PC に入れるときと同じ話です。
「便利そうだから」だけで入れず、**入れる前に中身を点検する**のがこのガイドの趣旨です。

> 「そもそもスキルってどう悪用されるの?」に実例つきで答える読み物として、
> [スキルを狙う攻撃カタログ](attack-catalog.md) を別に用意しました。どんな手口があり、
> チェッカーが何をどう防いでいるのかを 14 種類に分けて紹介しています。

## 2. 用意した道具は 2 つ

| 道具 | 何をするもの | 使わない場面 | 使う場面 |
| --- | --- | --- | --- |
| **skill-check** | スキルを 1 個ずつ点検して、配ってよいか判定する (複数まとめて頼んでも 1 件ずつレポートが返る) | 手元のスキル全体の整理 (→ もう 1 つの道具へ) | 新しいスキルを配る前 / 外から持ち込む前 / スキルが更新されたとき |
| **skill-portfolio-audit** | 手元に入っているスキル全部を棚卸しする | 特定の 1 個を配ってよいかの判定 (→ skill-check へ) | 「増えすぎた」「使っていないものがありそう」と感じたとき |

どちらも「点検してレポートを返す」だけです。skill-check は頼めばレポート提示後に
合意した範囲だけ直しますが、**スキルを消したり並べ替えたりするのは、いつも人間の仕事**
です (勝手には消しません)。

## 3. skill-check の使い方

チェックしたいスキルを渡して、そのまま頼むだけです。言い方の例:

- 「このスキルをチェックして」(フォルダやファイルを添付)
- 「この公開スキルを導入していいかチェックして」(URL を貼る)
- 「スキルが更新されたので再チェックして」

### 結果の読み方 — 判定の種類

| 判定 | 意味 | あなたがすること |
| --- | --- | --- |
| **配布可** | 配布を止めるほどの問題は見つからなかった (軽微な改善提案や「要確認」が付くことはある) | 改善提案・要確認に目を通してから配る (§5 の注意は残る) |
| **人のレビュー必須** | 危険とは限らないが、人の目での確認が要る | 詳しい人 (エンジニア等) に相談して、OK なら配る |
| **配布不可** | 危険な内容が見つかった | 配らない。作者に修正を依頼して再チェック |
| **判定不能 (取得不完全)** | 中身の一部しか見られなかった (ファイルが足りない) | 全ファイルを入手してから再チェック |
| **判定不能 (検査不能)** | ファイルは揃っているが、見えない文字などの検査がこの環境ではできなかった | 検査できる環境 (シェルが使える環境や詳しい人の手元) で再チェック |

大事なこと 1: **「配布可」= 何も指摘なし、ではありません**。軽い改善提案や「ここは
確認して」が付くことがあるので、レポートには目を通してください。

大事なこと 2: **「人のレビュー必須」は不合格ではありません**。たとえば「プログラムが
同梱されている」「メールを書き換える機能がある」スキルは、中身が正しくても**少なくとも**
この判定になります (機械のチェックだけで通さず、人が最後に見る仕組み)。逆に、はっきり
危険なプログラムや無確認の一斉送信などが見つかれば「配布不可」まで上がります。

### レポートには「直した方がいい点」も載る

危険の有無だけでなく、「この書き方だと AI がうまく反応しない」「もっと安全な作りに
できる」といった**改善提案**も返ります。作った人にそのまま渡せばスキルの品質が
上がります。

## 4. 特に気を付けるスキル — メール・カレンダーなど「実データを触る」もの

メール、予定表、顧客リストのような**本物のデータを直接いじるスキル**は、便利さと
引き換えにリスクが跳ね上がります。合言葉は:

> **「AI は下書きまで。実行ボタンは人が押す」**

- メールを「自動送信する」スキルより、「下書きを作って人が送る」スキルの方が安全。
- 予定を「勝手に変更する」より、「変更案を出して人が反映する」方が安全。

skill-check はこの観点でも点検し、「もっと安全な作りにできますよ」という提案を
返します。自分でスキルを作るときも、この原則で作ってください。

## 5. 運用の約束ごと (5 か条)

1. **外部のスキルは「直接入れない」**。ネットで見つけたスキルは、チェックしてから
   組織の管理場所にコピーし (取り込み)、そこから配る。元の場所を直接参照して
   いると、**後から中身を悪意あるものに差し替えられても気づけません**。
2. **更新されたら、もう一度チェック**。最初に安全でも、更新で危険なものが混ざる
   ことがあります (サプライチェーン攻撃と呼ばれる代表的な手口です)。
3. **プログラム入りのスキルは、必ず人 (エンジニア) のレビューを通す**。機械の
   チェックではプログラムの悪意までは見抜けません (はっきり危険なら「配布不可」に
   なりますが、そうでなくても人の確認は必須にします)。
4. **「チェック済み = 絶対安全」ではない**。チェックは見落としを減らすための道具で、
   安全を保証するものではありません。権限設定などの守り (エンジニアが整備) と
   併用してください。
5. **迷ったら入れない**。判断がつかないものは、詳しい人に聞くまで保留にする。

## 6. よくある質問

**Q. チェックにはどれくらい時間がかかりますか?**
A. AI に頼んでから、小さなスキルなら数分程度です。同梱ファイルが多い・プログラム入り
などの場合はもう少しかかります。

**Q. 自分が作った小さなスキルもチェックが要りますか?**
A. 自分だけで使うなら任意ですが、**人に配るなら必ず**通してください。うっかり
自分の PC の情報や取引先の名前が入っていた、という事故を防げます。

**Q. 「そもそもスキルにする必要ありますか?」と言われました。**
A. skill-check は「スキル化する価値」も見ます。1 回しか使わない手順や、いつも
守ってほしい短いルールは、スキルより適した置き場所 (その場の依頼文や常設の設定)
があるため、そう提案されることがあります。悪い評価ではなく、置き場所の助言です。

**Q. スキルが増えすぎて、どれが使われているのか分かりません。**
A. skill-portfolio-audit に「スキルの棚卸しをして」と頼んでください。全体を見て
「残す (keep) / 直す (fix) / 統合する (merge) / 削除候補 (remove)」を整理したレポートが
返ります。使用状況まで知りたいときは「ログも見て」と一緒に頼んでください
(勝手にはログを読みません。どのログをどの期間見てよいかを先に確認します)。

**Q. チェックで「配布不可」になりました。作者に何と伝えれば?**
A. レポートをそのまま渡してください。どこが・なぜ・どう直せばよいかが載って
います。直したら再チェックに出してもらえば OK です。
